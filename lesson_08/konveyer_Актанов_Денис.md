## Письмо 1. Ревью конвейеров

### 1. Выручка доставленных заказов от ноутбуков.

- Решение: есть ошибка — сумма по полю заказа после $unwind — итог повторён в каждой позиции — верно
- Комментарий: После $unwind каждый заказ превращается в несколько документов, а поле total повторяется для каждой позиции. Поэтому суммирование total завышает выручку ноутбуков и может учитывать один заказ несколько раз. Необходимо суммировать произведение items.qty на items.price.

### 2. Сколько заказов в пути в каждом городе.

- Решение: есть ошибка — $project перед стадией, которой нужно отброшенное поле — верно
- Комментарий: Стадия $project оставляет только number и delivery, удаляя поле status. Поэтому следующий $match не находит заказы со статусом «в пути». Необходимо выполнить фильтрацию до $project либо сохранить поле status в проекции.

### 3. Номер первого по дате заказа каждого покупателя из трёх: c-007, c-011, c-018.

- Решение: есть ошибка — $first или $last без $sort перед $group — верно
- Комментарий: Оператор $first без предварительной сортировки не гарантирует выбор самого раннего заказа по дате. Перед $group необходимо добавить $sort по полю created по возрастанию, а затем выбрать номер первого заказа каждого покупателя.

### 4. Пять самых дорогих доставленных заказов.

- Решение: есть ошибка — стадии стоят не в том порядке: $limit срабатывает раньше отбора — верно
- Комментарий: Стадия $limit оставляет пять самых дорогих заказов независимо от статуса. Последующий $match отбирает доставленные только среди этих пяти. Необходимо сначала отфильтровать доставленные заказы, затем отсортировать по total по убыванию и применить $limit.

### 5. Выручка доставленных заказов по способам оплаты.

- Решение: есть ошибка — путь к полю записан без знака $ — верно
- Комментарий: В выражении _id строка "payment.method" записана без знака $. MongoDB воспринимает её как обычный текст, поэтому все заказы попадают в одну группу. Необходимо использовать "$payment.method", чтобы группировать документы по фактическому способу оплаты.

### 6. Сколько штук смартфонов продано в доставленных заказах.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — верно
- Комментарий: Условие items.category до $unwind отбирает заказы, содержащие смартфоны, но после разворачивания в результат попадают и остальные позиции этих заказов. Необходимо повторить $match по items.category после $unwind, чтобы суммировать количество только смартфонов.

### 7. Средний чек доставленных заказов в каждом городе, округлённый до рубля, по убыванию.

- Решение: конвейер верный — верно
- Комментарий: Конвейер корректен. Сначала отбираются доставленные заказы, затем вычисляется средний чек по каждому городу. Среднее округляется до целого рубля, после чего результаты сортируются по убыванию avg.

### 8. Три самых продаваемых по штукам товара в доставленных заказах.

- Решение: конвейер верный — верно
- Комментарий: Конвейер корректен. После отбора доставленных заказов позиции разворачиваются через $unwind. Затем суммируется количество проданных единиц по каждому названию товара, результаты сортируются по убыванию qty и по названию при равенстве, после чего выбираются три лидера.

 },
 {$sort:revenue: -1}}

### 2. Коллекция products. Средняя цена товаров каждой категории, округлённая до рубля: _id — категория, avg — средняя цена. По возрастанию avg.

```js
db.products.aggregate([
  {
    $group: {
      _id: "$category",
      avg: { $avg: "$price" }
    }
  },
  {
    $project: {
      avg: { $round: ["$avg", 0] }
    }
  },
  { $sort: { avg: 1 } }
])
```

- Результат совпадает с нужным, запусков: 0

### 3. Покупатели, у которых сумма доставленных заказов больше 400 000: _id — customer_id, spent — сумма. По убыванию spent.

### 4. Для каждого города — массив номеров отменённых заказов по возрастанию номера: _id — город, numbers — массив. Города по алфавиту.

### 5. Одним запросом по доставленным заказам: в поле total — массив из одного документа { orders: число заказов }, в поле top — три товара с наибольшим числом штук (_id — название, qty — штуки), по убыванию qty, при равенстве — по названию.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  {
    $facet: {
      total: [
        { $count: "orders" }
      ],
      top: [
        { $unwind: "$items" },
        {
          $group: {
            _id: "$items.title",
            qty: { $sum: "$items.qty" }
          }
        },
        { $sort: { qty: -1, _id: 1 } },
        { $limit: 3 }
      ]
    }
  }
])
```

- Результат совпадает с нужным, запусков: 0
