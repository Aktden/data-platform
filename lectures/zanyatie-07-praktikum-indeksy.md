## Содержание практикума

Практикум закрепляет главу 3.2 справочника на базах `shop` и `logs`. Работа идёт
в браузере: стажёр группы платформы получает от руководителя четыре письма.

| Письмо | Что отрабатывает |
|---|---|
| 1 · тип индекса | восемь обращений команд магазина: тип индекса и его ключ, в том числе случаи, когда новый индекс не нужен |
| 2 · индекс под запрос | пять заданий на журнале из 1200 событий: ключ собирается из полей, сервер показывает план, число прочитанных ключей и документов и полосу индекса |
| 3 · вес индексов | прогноз размера четырёх индексов на 1 000 000 событий, калькулятор размеров и два вопроса по нему |
| 4 · ревизия | семь индексов журнала и шесть рабочих запросов с частотой: какие индексы оставить, какие удалить |

Планы запросов, размеры индексов и время вставки в практикуме получены
на сервере стенда курса, MongoDB 7. К любому открытому письму можно вернуться
до сдачи. После кнопки «Сдать работу» открывается рецензия руководителя
с баллами и разбором.

## Термины

| Термин | Значение |
|---|---|
| составной индекс | индекс по нескольким полям; записи упорядочены по первому полю, внутри одинаковых значений — по второму |
| префикс индекса | первое поле составного индекса или несколько первых полей подряд; индекс используется, когда префикс есть в условиях запроса |
| уникальный индекс | индекс с параметром `unique`: два документа с одинаковым значением поля в коллекцию не записываются |
| частичный индекс | индекс с условием `partialFilterExpression`: в него попадают только документы, которые условию соответствуют |
| многоключевой индекс | индекс по полю массива: каждый элемент массива заносится в индекс отдельно |
| `IXSCAN`, `FETCH`, `SORT`, `LIMIT`, `COLLSCAN` | стадии плана запроса: чтение индекса, чтение документов по ссылкам, сортировка в памяти, остановка после нужного числа документов, просмотр всей коллекции |
