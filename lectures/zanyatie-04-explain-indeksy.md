## Содержание практикума

На маленьких коллекциях любой запрос отвечает мгновенно, и по времени
ответа нельзя понять, дорого он обходится или дёшево. Коллекция `logs.events`
содержит 1200 записей журнала — на ней разница видна в числах.

### План выполнения

`explain("executionStats")` возвращает документ с планом: какие шаги прошёл
сервер, сколько документов прочитал и сколько вернул.

| Число | Что означает |
|---|---|
| `nReturned` | сколько документов вернул запрос |
| `totalDocsExamined` | сколько документов сервер прочитал |
| `totalKeysExamined` | сколько записей индекса просмотрел |

| Шаг плана | Что означает |
|---|---|
| `COLLSCAN` | полный перебор коллекции: прочитаны все документы |
| `IXSCAN` | поиск по индексу: прочитано близко к `nReturned` |
| `SORT` | сортировка в памяти |

План выгружают в файл и разбирают на сайте, который рисует шаги схемой
и подсвечивает дорогие места.

### Индексы

| Команда | Что делает |
|---|---|
| `db.col.getIndexes()` | список индексов |
| `db.col.createIndex({ a: 1, b: -1 })` | создать составной индекс |
| `db.col.dropIndex({ a: 1, b: -1 })` | удалить индекс |

**Правило ESR** задаёт порядок полей составного индекса: сначала поля
с проверкой на равенство (Equality), затем поле сортировки (Sort), затем поле
с диапазоном (Range).

## Что делали на занятии

1. Сбросили базу `logs` к исходному состоянию.
2. Сняли планы запросов без индекса и нашли полный перебор.
3. Создали индексы и сравнили числа в планах до и после.
4. Проверили порядок полей составного индекса по правилу ESR.
